# Definition of Done

## Done Means

- Requirements are documented
- Risks are documented
- Architecture is documented
- User stories are written
- Acceptance criteria are explicit
- Story points are assigned
- Teams impacted are named
- Post-release support is defined
- Change log is present

## Quality Checks

- No vague language
- No dead pages
- No missing ownership
- No unsupported automation claims
- No contradiction between docs

## POC Done Means

- The story is coherent
- The package is lean
- The mock can be explained to someone outside the build

# Definition of Done

## Done Means

- Requirements are documented and traceable
- Risks are documented and owned
- Architecture is documented and matches the route map
- User stories are written with scenarios
- Acceptance criteria are explicit and testable
- Story points are assigned to every story
- Teams impacted are named
- Post-release support is defined
- Change log is present
- AI usage is documented
- UI prompt and page tree are aligned

## Quality Checks

- No vague language
- No dead pages
- No missing ownership
- No unsupported automation claims
- No contradiction between repo, Kiro, and Drive
- No detached role-card landing page if the portal shell is the locked target

## POC Done Means

- The story is coherent
- The package is lean
- The portal can be explained to someone outside the build
- The remaining screens each have a visible purpose and outcome

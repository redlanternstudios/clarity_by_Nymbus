# Acceptance Criteria

## Borrower Story

- Status is visible without interpretation work
- Next step is clear
- No unsupported actions appear
- Read-only behavior is obvious

## Servicing Agent Story

- Notes can be added in the expected place
- Case context is visible
- Routing options are understandable
- No dead-end path exists

## Stakeholder Story

- Launch health is visible
- Bottlenecks are easy to spot
- Reporting language is plain
- The view is high level and readable

## Support Story

- Chatbot suggests a category
- Human can override the suggestion
- Tickets can be routed to floor, customer, product, or technical queues
- Ambiguous tickets are escalated, not auto-closed
